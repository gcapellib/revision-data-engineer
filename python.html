6 idées font tout le cours

Tout le cours répond à : comment écrire un programme Python qui se comporte comme prévu, aujourd'hui et quand il grossira ? Six règles expliquent presque toutes les surprises.

Idée 1 · Une variable est une étiquette posée sur un objet

Le type appartient à l'objet, pas au nom ; deux noms peuvent désigner le même objet. b = a ne copie rien, is compare l'identité, == la valeur, et input() renvoie toujours une chaîne.

L'erreur typique : Si l'on écrit b = a puis qu'on modifie b, on modifie aussi a, car les deux noms désignent la même liste.

La bonne pratique : Copier explicitement quand on veut un objet indépendant : b = a.copy() pour une liste (ou copy.deepcopy pour une structure imbriquée).

ch. 01 · ch. 02

Idée 2 · Mutable ou immuable : la question qui évite les bugs

list, dict et set se modifient sur place ; str, int et tuple non. Un objet mutable partagé (valeur par défaut d'une fonction, attribut de classe) est modifié pour tout le monde.

L'erreur typique : Si une fonction a une liste comme valeur par défaut (def f(x, l=[])), cette liste n'est créée qu'une fois et s'accumule d'un appel à l'autre.

La bonne pratique : Mettre None comme valeur par défaut et créer la liste dans la fonction : def f(x, l=None): l = [] if l is None else l.

ch. 01 · ch. 02

Idée 3 · La bonne structure fait la moitié du travail

Une liste pour une suite ordonnée, un dict pour retrouver par clé en temps constant, un set pour l'unicité et les opérations d'ensembles, un tuple pour un enregistrement fixe.

L'erreur typique : Si l'on cherche un élément dans une liste d'un million d'éléments, Python les parcourt un par un, alors qu'un set répond immédiatement.

La bonne pratique : Pour tester l'appartenance souvent, convertir la liste en set une fois (vus = set(liste)), puis tester x in vus.

ch. 01 · ch. 03

Idée 4 · Regrouper données et comportement, cacher le reste

Une classe regroupe des données et les méthodes qui les manipulent, et protège son état interne (attribut _x, accès contrôlé par @property). On utilise l'héritage pour une relation « est un » (un Chien est un Animal), la composition pour « a un » (une Voiture a un Moteur), et @dataclass pour un simple objet de données.

L'erreur typique : Si une classe fait tout, ou si l'on hérite d'une classe juste pour réutiliser son code, le programme devient difficile à modifier sans tout casser.

La bonne pratique : Donner à chaque classe une seule responsabilité, et préférer la composition (un objet en contient un autre) quand ce n'est pas une vraie relation « est un ».

ch. 02 · ch. 04

Idée 5 · Traiter l'erreur là où l'on sait quoi en faire

On lève une exception précise (ValueError, FileNotFoundError…), on la capte là où l'on sait quoi faire, et l'on libère les ressources avec with (fichier, connexion). Jamais de except: sans type, qui avale toutes les erreurs.

L'erreur typique : Si l'on écrit except: sans préciser l'erreur attendue, même une faute de frappe dans le code est avalée en silence, et le bug devient introuvable.

La bonne pratique : Capter seulement l'erreur attendue (except FileNotFoundError:) et laisser remonter les autres.

ch. 03 · ch. 04

Idée 6 · Un code pro se lit, se teste et se rejoue

Un code professionnel se lit, se teste et se relance ailleurs : fonctions courtes, style PEP 8, logging plutôt que print, tests avec pytest, environnement virtuel (venv) et versions des bibliothèques figées, générateurs pour traiter de gros volumes sans tout charger en mémoire.

L'erreur typique : Si l'on ne fige pas les versions des bibliothèques et qu'on n'écrit pas de tests, le script ne fonctionne que sur le poste de son auteur.

La bonne pratique : Créer un venv, figer les versions dans requirements.txt et lancer pytest avant chaque partage.

Classes, objets et encapsulation

Pourquoi la POO

Regrouper données et comportements dans une même unité, la classe, pour modéliser un domaine (client, produit) : code réutilisable, testable, extensible. Une classe est le plan ; un objet (instance) est une réalisation.

Les briques
  • init(self, …) : constructeur, initialise les attributs.
  • Attribut d'instance (self.x) contre attribut de classe.
  • @staticmethod (sans self), @classmethod (reçoit cls, usine d'objets).
  • Méthodes magiques : str, eq, len, repr.
python
class Compte:
    def __init__(self, titulaire, solde=0):
        self.titulaire = titulaire
        self._solde = solde            # protégé par convention

    @property
    def solde(self):                   # lecture contrôlée
        return self._solde

    def deposer(self, montant):
        if montant <= 0:
            raise ValueError("montant positif requis")
        self._solde += montant

    def __str__(self):
        return f"{self.titulaire} : {self._solde} €"

c = Compte("Ana"); c.deposer(50); print(c)   # Ana : 50 €

Héritage, abstraction et dataclasses

python
from abc import ABC, abstractmethod

class Produit(ABC):                    # classe abstraite
    def __init__(self, titre):
        self.titre, self.disponible = titre, True
    @abstractmethod
    def louer(self): ...               # à implémenter par les filles

class Film(Produit):                   # héritage
    def louer(self):
        self.disponible = False        # polymorphisme

from dataclasses import dataclass
@dataclass
class Point:                           # __init__, __repr__, __eq__ générés
    x: float
    y: float = 0.0

Une classe abstraite ne peut pas être instanciée ; une classe fille qui n'implémente pas toutes les méthodes abstraites reste abstraite.

Les quatre piliers
  • Encapsulation : cacher l'état, exposer des méthodes (_x protégé, __x « privé » par renommage ; @property).
  • Héritage : réutiliser une classe mère (super()).
  • Polymorphisme : même appel, comportement selon la classe.
  • Abstraction : définir un contrat sans l'implémenter (ABC).
Principes SOLID
  • S une classe, une responsabilité · O ouverte à l'extension, fermée à la modification.
  • L une fille doit pouvoir remplacer sa mère · I interfaces petites · D dépendre d'abstractions.
  • Aussi : KISS, DRY, YAGNI.

Visibilité, redéfinition et surcharge d'opérateurs

python
class User:
    def __init__(self, nom):
        self.nom = nom            # public
        self._role = "user"       # protégé : convention, accès possible
        self.__mdp = "x"          # privé : renommé en _User__mdp

    def get_full_name(self):
        return self.nom.upper()

class Admin(User):
    def get_full_name(self):      # redéfinition (surcharge) de la méthode
        return super().get_full_name() + " (admin)"   # étend la mère

class Euro:
    def __init__(self, v): self.v = v
    def __add__(self, autre): return Euro(self.v + autre.v)   # a + b
    def __lt__(self, autre): return self.v < autre.v          # a < b

Python n'a pas de vraie visibilité : _x est une convention, x déclenche un renommage (name mangling__) qui évite les collisions dans les sous-classes.

Redéfinir une méthode
  • La fille redéfinit une méthode de la mère quand celle-ci ne convient plus.
  • super().methode() réutilise la version de la mère puis l'étend.
  • C'est le mécanisme qui rend le polymorphisme possible.
Surcharger un opérateur

Les méthodes magiques add, eq, lt, len donnent un sens à +, ==, <, len() pour vos classes. Python ne surcharge pas une méthode par nombre d'arguments : on utilise des valeurs par défaut ou *args.

Chapitre 02 · La programmation orientée objet
Ce que le jury peut demander

Questions d'oral — chapitre 02

L'encapsulation (protéger l'état), l'héritage (réutiliser et spécialiser), le polymorphisme (même interface, comportements différents) et l'abstraction (définir un contrat sans l'implémenter).

Une classe abstraite peut contenir du code et de l'état partagés, et impose aux filles d'implémenter ses méthodes abstraites ; une interface pure ne décrit que des signatures. En Python, les deux se modélisent avec ABC.

L'héritage exprime « est un » et couple fortement mère et fille ; la composition exprime « a un » et reste plus souple. On préfère la composition, sauf vraie relation de spécialisation.

À déclarer une classe de données sans code répétitif : init, repr et eq sont générés à partir des champs typés. On peut le rendre immuable avec frozen=True.

Une classe ne doit avoir qu'une raison de changer : par exemple séparer le calcul d'une facture, son stockage et son affichage. Le code est alors plus simple à tester et à faire évoluer.

① Pourquoi ② Quoi

Gérer les erreurs avec les exceptions

Principe

Une exception interrompt le flux normal ; on la capte pour réagir. Les types sont organisés en hiérarchie (Exception → ValueError, KeyError, FileNotFoundError…).

Les quatre clauses
  • try : code risqué.
  • except Type as e : traitement, du plus précis au plus général.
  • else : s'exécute si aucune erreur.
  • finally : toujours (libérer ressources).
Analogie — un filet de sécurité sous un funambule : on ne l'utilise pas pour marcher, mais il évite la chute fatale.
python
class SoldeInsuffisant(Exception):         # exception métier
    pass

def retirer(solde, montant):
    if montant > solde:
        raise SoldeInsuffisant(f"manque {montant - solde} €")
    return solde - montant

try:
    solde = retirer(50, 80)
except SoldeInsuffisant as e:
    print("Refusé :", e)                  # Refusé : manque 30 €
except (TypeError, ValueError):
    print("Données invalides")
else:
    print("OK", solde)
finally:
    print("fin")                           # toujours exécuté

Fichiers, CSV et JSON

python
import csv, json
from pathlib import Path

with open("titanic.csv", newline="", encoding="utf-8") as f:   # fermé auto
    lignes = list(csv.DictReader(f))        # liste de dict, 1 par ligne

Path("a.json").write_text(json.dumps(data, ensure_ascii=False, indent=2))
back = json.loads(Path("a.json").read_text())   # str -> dict

with est un gestionnaire de contexte : il ferme le fichier même en cas d'erreur. Toujours préciser encoding="utf-8".

CSV

Texte tabulaire à séparateur ; csv.reader (listes) ou csv.DictReader (dictionnaires par en-têtes). Tout est lu en chaînes : convertir. Pour de gros volumes : pandas.

JSON
  • Sérialiser : objet Python → texte (json.dump(s)).
  • Désérialiser : texte → objet (json.load(s)).
  • Correspondance : dict ↔ objet, list ↔ tableau, None ↔ null, True ↔ true.
  • Les objets personnalisés (dates, classes) ne sont pas sérialisables directement.

Générateurs, context managers, logging

Générateur

Une fonction avec yield produit les valeurs une à une, à la demande : mémoire constante pour de gros flux (lignes d'un fichier de 10 Go). Un itérateur se consomme une seule fois.

python
def lignes_non_vides(chemin):
    with open(chemin, encoding="utf-8") as f:
        for ligne in f:                 # lit ligne à ligne
            if ligne.strip():
                yield ligne.strip()     # produit une valeur

total = sum(1 for _ in lignes_non_vides("log.txt"))   # sans tout charger
Context manager

L'instruction with appelle enter puis exit : acquisition et libération garanties (fichier, connexion, verrou). @contextmanager en fait un générateur à deux temps.

Logging
  • import logging : niveaux DEBUG < INFO < WARNING < ERROR < CRITICAL.
  • Remplace print : horodatage, niveau, destination (fichier, console), filtrage.
  • logger.exception("échec") journalise la trace.
  • Ne jamais journaliser de mot de passe ni de donnée personnelle.

Expressions régulières avec re

python
import re
texte = "Commande 42 le 2026-03-15, contact : ana@ex.fr"
re.search(r"\d+", texte).group()          # '42'  première correspondance
re.findall(r"\d{4}-\d{2}-\d{2}", texte)   # ['2026-03-15']  toutes, en liste
m = re.search(r"(\w+)@(\w+\.\w+)", texte)
m.group(1), m.group(2)                   # ('ana', 'ex.fr')  groupes de capture
re.sub(r"\s+", " ", "a   b \t c")         # 'a b c'  remplacer
re.match(r"\d", texte)                    # None : match ancre au DÉBUT
motif = re.compile(r"^[A-Z]{2}\d{3}$")     # compiler un motif réutilisé
bool(motif.match("AB123"))                # True

On écrit les motifs en chaîne brute r"…" : sans le r, Python interpréterait \d comme une séquence d'échappement.

SymboleSens
\d \w \schiffre, caractère de mot, espace
.n'importe quel caractère
* + ?0 ou plus, 1 ou plus, 0 ou 1
{2,4}entre 2 et 4 fois
^ $début, fin de chaîne
[A-Z]un caractère de la classe
( )groupe de capture
Quelle fonction choisir
  • re.match : correspondance au début seulement.
  • re.search : première correspondance n'importe où.
  • re.findall : toutes les correspondances, en liste.
  • re.sub : remplacer ; re.split : découper.
  • Usage data : valider un format (code postal, date), extraire, nettoyer. À garder simple et testé.
